# Component catalog

The openui backend's component table, generated by hand from
`src/backends/openui/signatures.ts`. When the table changes, this file changes.

**30 of 48 render.** The language *understands* all 48 — `signatures.ts` lists
every one, so the validator accepts them — but the renderer (`COMPONENTS` in
`src/client/OpenUICard.tsx`) draws only the thirty below.

That count is **measured, not remembered**: `tests/openui-inventory.spec.tsx`
imports both tables (the language's, and the renderer's now-exported
`RENDERED_COMPONENTS`) and prints the split. An earlier probe mirrored the
renderer's table as a hand-written literal and kept answering "8 of 48" long
after the renderers existed — a copy of an answer is not a measurement.

## The gap a model can fall into

An unrendered component is **accepted by validation and drawn as nothing**. This
is measured, not inferred: `evidence/phase-3/unrendered-component-check.txt`.

| Program | `validate` errors | What the reader sees |
| --- | --- | --- |
| `root = Col([Grid([])])` | none | a drawn, empty grid |
| `root = Col([Map([])])` | `VZO002 unknown component "Map"` | the call is rejected |

*The `Carousel`/`Popover` rows that stood here as examples of the gap are gone:
4A-5 drew both, and the notice is now unreachable through a program. Its own guard
is asserted directly in `tests/openui-layout-4a1.spec.tsx`.*

The safety net covers names the **language** does not know (`Map` is
open-intelligent-ui's, not ours). For names the language declares but the
renderer does not draw, 4A-1 added an explicit notice rather than silence — see
below.

That is a known, recorded limitation rather than a design position: the fix is to
finish the renderers (4A), not to reject names the dialect declares. Rejecting
them would make the language disagree with its own signature table, which is the
drift ADR-002 exists to prevent.

### A declared name with no renderer now says so

Before 4A-1, `drawValue` returned `null` for a declared-but-undrawn component, so
a legal program drew a silently empty card — indistinguishable from a card that
was *meant* to be empty. The two are now different by construction:

| Case | What is drawn |
| --- | --- |
| Legal empty container, e.g. `Grid([])` | the container itself, e.g. `display:grid` with zero children |
| Declared component with no renderer — unreachable since 4A-5; the notice is `X is not drawn by this build`, carrying `data-openui-unrendered="X"` | a muted notice, so a renderer gap never looks like an intentional blank |
| Name the language does not declare, e.g. `Map` | nothing; the host rejects the program at validation (`VZO002`) |

The notice is not a substitute for the renderer — it is a diagnostic that stops a
renderer gap from looking like an intentional blank.

## Actions — declared, and two refused

An action is the step a `Button` carries. Four work; two are refused.

| Action | Validates | Executes | Notes |
| --- | --- | --- | --- |
| `@Set($var, value)` | yes | **yes** | Writes one declared variable |
| `@Reset()` | yes | **yes** | Returns variables to their declared defaults |
| `Action([...])` | yes | **yes** | Runs several steps in order |
| `@CopyToClipboard(text)` | yes | **yes** | **ADR-013.** Copies its text on a press, and the Button then shows that text in full so the reader sees exactly what will be copied. Refused inside `Action([...])`; capped at 32 KiB, refused not truncated |
| `@OpenUrl(url)` | yes | **no** | **Deferred.** The host capability exists but is a sidebar tab, not an external open — see below. ADR-014 §10 |
| `@ToAssistant(message)` | yes | **no** | **Deferred.** Submission is reachable; attribution and an unfakeable confirmation are not — see below. ADR-015 §10 |

The two refused actions are declared by the language so that a program naming one
**validates** rather than failing with `VZO002`. They are then refused at dispatch,
which means the Button renders normally and does nothing when pressed.

That combination is deliberate but easy to get wrong, so the skill text says so
explicitly and `tests/skill-actions-consistency.spec.ts` pins the two together:
a documentation change that drops the warning, or a dispatcher change that
silently starts executing one of them, fails that test.

**Use `Link("label", "https://…")` to offer a URL** — it is a link the reader
clicks, subject to ADR-008's protocol allowlist, and it is what `@OpenUrl` would
have produced on a user's press.

### Why the two are deferred, corrected 2026-11-06

Both were deferred on the stated ground that the host exposes no relevant API.
**That was wrong**, and the corrections are recorded in ADR-014 §10 and ADR-015 §10
rather than quietly edited away. Neither verdict changed; only the reason did.

**`@OpenUrl`.** A host-mediated open *does* exist —
`ctx.sidebarRight.openTab('browser', { params: { url } })` — and it is the call the
host's own link gesture makes. It is **not this action**: it docks a tab inside the
DSH window instead of opening the page in the reader's browser, and an iframe
refusal in that tab is unobservable, which is the silent failure ADR-014 exists to
prevent. It stays refused pending an upstream plugin-callable open-external API,
and is not re-pointed at the sidebar in the meantime.

**`@ToAssistant`.** Submission *is* reachable: every session-scope card already
receives `inputActions`, which carries `submit()`. Role escalation is structurally
impossible — the host builds the message source, so no caller can name a role. It
stays refused on the two ADR-015 properties no host API supplies: the turn would
carry **no visible attribution** (`rpcId` is dedupe-only and never rendered), and
there is **no confirmation the card cannot fake**. A card-drawn dialog is the card's
own surface, which is exactly what ADR-015 forbids, so it is not a substitute.
Neither requirement is dropped.

Both remain refused at dispatch, and the refusal notice is unchanged.

## Not yet available — validated but not drawn

**Nothing.** As of 4A-5 every name `signatures.ts` declares has a renderer, so
the rendered set equals the declared set: **48 / 48**.

The "not drawn by this build" notice still exists and is still tested, because the
gap it reports is created by adding a signature without a renderer — a two-file
mistake no test can prevent, and one that would otherwise ship as a silently blank
card. `tests/openui-layout-4a1.spec.tsx` asserts both that the notice renders and
that it is currently unreachable.

The authoritative list is measured, not typed: `tests/openui-inventory.spec.tsx`.
If this table and that output disagree, the output is right.
