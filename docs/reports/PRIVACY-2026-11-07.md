**Residual to state explicitly:** `96e7c9a` permanently contains the profile
path unless history is rewritten; and GitHub keeps serving unreferenced

## 4. Minimal cleanup plan

**A. Sanitise HEAD (recommended; no history rewrite).**
Replace `C:\Users\<name>` / `C:/Users/<name>` with `C:\Users\<user>` /
`C:/Users/<user>` in the 15 files, plus a one-line note in `session-log.md`.
Docs/evidence only — no `src/`, no `tests/`, so no behaviour changes. One
commit, normal push. Effect: the current tree, future clones and GitHub's
default code view/search are clean; historical commits are unchanged.

**B. History rewrite (optional; needs explicit approval).**
`git filter-repo` across all refs, then a force push. Cost: breaks existing
clones/forks, changes every commit id after the first rewrite point, and **does
not** remove unreferenced SHAs (`58ab17a` etc.) that GitHub still serves by URL.

**C. Complete purge (only if the folder name must disappear entirely).**
The only method that removes cached/unreferenced objects is **delete and
re-create the repository** after B, which needs the `delete_repo` OAuth scope;
collaborators and stars/forks are lost. No credential rotation is needed —
nothing secret was exposed.

**Recommendation:** do **A** now if the owner wants the tree clean; hold B/C
unless the folder name itself is considered sensitive. The value has been in
public history since `v0.1.1`, so B without C buys little, and C is a
repo-level decision. **Neither B nor C is authorised by this review.**
